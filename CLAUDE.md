# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Risk assessment (RA) indicators for a bank. `master.xlsx` (35 activities, 1,380 indicators) is imported into
`activities/`; the runner computes them from read-only sources (Oracle COREMIS / FINACLE / ERP / CARDZONE / JIRA,
ClickHouse DWH) and writes to one ClickHouse table, `risk_assessment.ri_result`, whose columns the user fixed:
`activity, activity_id, solid, branch_id, risk_indicator, risk_ind_id, result_number, result, snapshot_date`
(+ technical `run_id, loaded_at`). One row per indicator × activity (BRANCHID) × report date; `solid` is metadata (the
activity's SOLIDs that day, "862,896"); `result` = score "1"…"5"; `risk_ind_id = 'TOTAL'` = activity total
(`result_number` = Σ(w×score)/Σw, `result` = Өндөр/Дунд/Бага). SOL drill-down, numerator/denominator, weight are NOT
stored (internal rows → `store.to_result_rows`; drill-down via `--save-csv`, verify, demo_check `engine_rows`).

- **SOLID** = smallest org unit; **BRANCHID** groups SOLIDs; **one activity = one BRANCHID** (`config/activity_map.csv`,
  groups 2, 10, 11, 20, 21 are still unmapped = ТОДРУУЛАХ). SOLID → BRANCHID comes from `COREMIS.MAIN` at the report
  date (`shared/org/units.sql`, config `org:`; `orgmap.py`, cached per date), falling back to `config/activity_units.csv`.
- **One definition = one file; duplicates are merged** (`ri_runner/dedup.py`, `docs/dedup.md`): master's 1,380 rows
  have 498 distinct names (`dedup.norm_key`). A name used by 2+ activities is ONE definition
  `activities/_shared/sh_NNN.sql` (50 defs → 932 indicators); each activity lists its instances in `activity.yaml`
  `shared: - {id: RI_40_1545, def: SH_007, weight: 1.5}` plus per-activity overrides (`metadata.MANIFEST_KEYS`:
  scale_text/scale, period/period_text, method, score_type, params, enabled, note …; key is `id:` because PyYAML reads
  `no:` as False). Single-activity names are `activities/act_GG_slug/ri_GG_NNNN.sql` (448; 9001+ = extras, no weight).
  `metadata._load_manifest` builds each instance with `dataclasses.replace` from the def (`def_id`, `manifest`,
  `def_path`; `file_name` = def file; `sql_version` includes the manifest entry hash).
- YAML front matter `/*--- … ---*/` then SQL. The `# ── Master ──` block (weight, scale_text, score_type, period_text …)
  and the manifest block are generated by `ri.py import` — never hand-edit; `import --update` refreshes them
  (idempotent; keeps hand-added params / enabled / note / period / scale).
- Modes (`metadata.py`): `sql` (own SQL or `sql_from` + `params`), `shared` (manifest instance of a SQL def — the def's
  SQL runs once, every activity takes its own SOL / BRANCHID rows; 34 SQL defs → 762 indicators), `manual`
  (`manual: true` on a file or a def; 609 indicators, entered via `ri.py manual template/load` Excel). Legacy
  `calc: SH_NNN` on a file still works.
- SQL returns standard columns (`store.STD_REQUIRED/STD_OPTIONAL`): `ENTITY_LEVEL, ENTITY_ID, VALUE` + optional
  `NUMERATOR, DENOMINATOR, VALUE_TEXT, ENTITY_NAME, METRIC, SOURCE_ROW_COUNT, DATA_STATUS`. Levels: `SOL` (filtered to the
  activity's SOLs), `ACTIVITY` (own BRANCHID row), `BANK` (bank-wide), anything else (all rows, e.g. `UNIT`).
- `period` (report / last_year / since_audit / latest) is inferred from master `period_text` (`metadata.infer_period`,
  typo-tolerant) unless `period:` is set; shared users with empty `period_text` inherit the calc's `period`.
  `runner.period_start_for` turns it into `:p_period_start`; since_audit uses the last internal audit before the
  report date from GRC (config `audit: {connection, shared: grc.last_audit}` → `orgmap.audit_date`), else
  `activity_map.csv LAST_AUDIT_DATE`, else last year.
- Docs, comments and CLI output are Mongolian. Keep new comments and messages in Mongolian.
  Rules: `docs/sql_standard.md`; onboarding: `docs/onboarding.md`; demo: `docs/examples.md`; process: `docs/workflow.md`.

## Architecture

- **Run** (`runner.run_plan` → `run_date` per report date):
  1. `select` drops manual indicators and skips invalid metadata / disabled / status < `min_status` / `params: TODO`
     (PARAMS_TODO); `_dependency_problems` skips cycles (DEPENDENCY_CYCLE), missing deps and dependants of non-runnable
     ones (never crashes the run).
  2. `group_by_calc` groups targets by `calc_id@start` (+ instance params, + activity when the SQL uses
     `:p_activity_branch_id`) so one SQL runs once per period start; groups run in dependency order on a thread pool
     (`TopologicalSorter`) with `db.ConnectionPool` (one source connection per thread; `connect` retries
     ORA-12516/12519/12520 / DPY-6005); a failed dependency → `DEPENDENCY_FAILED`.
  3. `execute_calc`: `prep_sql` (`expand_shared` → `render_schemas` → `clean_trailing`), optional `source_check`
     (0 → SKIPPED SOURCE_NOT_READY), `query_typed` on a **read-only** source connection, `check_standard_columns`,
     `_to_rows`, `validate_calc` (duplicate key, empty id, `min_rows`, `value_range`).
  4. Per target, `target_rows` (shared with `verify`; ACTIVITY level = the activity's own BRANCHID row, missing →
     "no data") → `activity_rows` (SOL filtering via `orgmap.sols_for`, `aggregate`:
     Σnum/Σden; Σvalue when no denominator or `rollup_metrics: {value: sum}`; texts collected) → `score_value`
     (numeric value and each `VALUE_TEXT` scored, highest wins) → internal rows (ACTIVITY row flagged `primary` for
     the score metric + drill rows, `sol_id`, `file_name`); `store.to_result_rows` keeps only the primary ACTIVITY
     row (and TOTAL rows). `sql_version` (`version_of`: file hash + calc hash + params hash) goes to the audit;
     `auto` reads it back by joining ri_result.run_id with the audit (`store.written_versions`).
  5. `_write_target`: `store.insert_result_verified` (insert, read back by scope + run_id, `written_diff`; mismatch →
     discard → `INSERT_MISMATCH`), `check_sql`. Older rows of written scopes are collected in `ctx.replaced` and
     removed by `_replace_old` with ONE `keep_only_run_many` per report date (→ `ri_history`, deleted); groups whose
     dependency reads `ri_result` flush their deps first. Empty target → `store.clear_scope` (WARN no_rows, so a
     manual→auto switch never leaves stale rows). A failed delete sets `ctx.replace_failed` → exit 1.
     prod (`insert_on_validation_fail: false`) discards failing runs. Audit row per indicator (`ri_execution_audit`).
  6. `refresh_activities` → `aggregate_activity`: ACTIVITY row = Σ(weight × score) / Σ(weight of scored), level by
     `config/scoring.yaml` (≥3.5 Өндөр, ≥2.5 Дунд). Example activities (`example: true`) are not aggregated.
- **Params** (`calc_params`, `effective_params` = def params + manifest-instance params): `p_report_date`
  (+`p_report_date_next`, aliases `p_date_to`), `p_period_start` (`p_date_from`), `p_prev_period_end`, `p_quarters`,
  `p_activity_branch_id`, file `params`, overridden per env by `config/<env>.yaml params:` keyed by RI_ or SH_ id
  (`metadata.apply_env_params`, applied in `cli._env`).
- **Read-only sources** (`db.py`): Oracle runs every query in `SET TRANSACTION READ ONLY` then rolls back (ORA-01456 →
  `SOURCE_WRITE_BLOCKED`), PL/SQL blocks bind `:rc` (SYS_REFCURSOR), ORA-01466 retried; ClickHouse `readonly=2`. After
  `call_timeout` thin mode drops the connection — only reset when `is_healthy()` (else SIGBUS). `classify_error` maps
  DPY-4011/4024, Code 159, "Estimated query execution time" to TIMEOUT.
- **Deletes** (`store.delete_verified`): ClickHouse 25.8 lightweight DELETEs issued concurrently from several threads
  occasionally left the old rows behind (duplicates caught by `verify`). Deletes are serialized with `_DELETE_LOCK`,
  re-counted, retried `DELETE_RETRIES` times, else `DELETE_INCOMPLETE`. Never add a bare `DELETE` — use this helper.
- **Scale** (`scale.py`): port of DaHUB `computeScoreFromScale` + master text parser (one score per line; "a-b"
  inclusive with the shared point going to the next band; "N-аас бага" strict; % scales compare ratio×100; "N хоног";
  category lines matched exactly, by "contains" (", аудит ороогүй") and typo-tolerant `_fuzzy` ≥0.92; 0-rows =
  Үнэлэхгүй, excluded from weights). Broken master scales stay unparsed (`scale_error` → check WARN); for a shared def
  the dedup takes the common parsable scale, so broken copies (83) score correctly; write `scale:` by hand otherwise.
- **verify** (`verify.py`): `fetch_calc` (read-only, no write) → `target_rows` → `compare` against `store.read_indicator`
  (ACTIVITY fields + drill rows), audit of the writing run, ACTIVITY total recomputed from stored indicator scores.
- **auto** (`auto.py`): due dates in [since, as_of] per frequency; reasons from `store.written_versions` +
  `store.last_attempts`: ШИНЭ, АЛДАА (last attempt FAILED/TIMEOUT/VALIDATION_FAILED), ӨӨРЧЛӨГДСӨН (`version_of` differs),
  ХАМААРАЛ (dependency reruns). Prod Airflow DAG runs it daily (`deploy/airflow_dag.py`).
- **Checks** (`checks.py`): rules on comment/string-stripped SQL (no `SELECT *`, DML/DDL, `EXECUTE IMMEDIATE`, `FOR UPDATE`,
  passwords, DB links, literal dates), `dialect_errors` (`:p_x` only on Oracle, `{p_x:T}` only on ClickHouse), `:rc` for
  blocks, `{{shared.x}}` existence, unused shared files (config `org.shared` counts), identical SQL, weights ≠ 100, missing
  BRANCHID (warning), duplicate BRANCHID (error).
- **Import** (`importer.py`): xlsx or TSV-with-.xlsx-extension; `read_master` → `dedup.decide` → defs used by ≥2
  activities (`shared_min`) become `_shared/sh_NNN.sql` (`def_text`) + `activity.yaml` manifest (`write_manifest`),
  the rest `ri_GG_NNNN.sql`; folder slug from `activity_map.csv NAME_EN`; never overwrites files except `--update`
  (master block / manifest only, YAML-semantic diff). `ri.py dedup master.xlsx` → `output/dedup_report.html`
  (each decision, 24 name families, 18 near-duplicates — reported, never merged).
- **ClickHouse objects** (`ddl/clickhouse/`, `store.ensure_base` creates, adds new columns with `ADD COLUMN IF NOT EXISTS`):
  `ri_result`, `ri_execution_audit`, `ri_history`, `ri_activity` / `ri_indicator` (ReplacingMergeTree, synced from
  `activities/` by `sync_meta`), views `v_activity_score`, `v_indicator_score`. A legacy-layout `ri_result` (no
  `risk_ind_id`) is renamed to `ri_result_legacy_<ts>` by `ensure_base`, never dropped. Scopes: indicator
  `(risk_ind_id, snapshot_date)`, total `(branch_id, 'TOTAL', snapshot_date)`. Aggregation weights come from the
  catalog (`runner.activity_scored`), not from ri_result.

## Local demo (tests/local/)

- `bank_demo.py` builds the whole demo bank deterministically (`SEED`): org snapshots (2026-01-01 old structure with SOL
  819; 03-01 adds 818 and HR SOL 898), HR simulation (slots, promotions, transfers, swaps — `simulate_hr`), GL, loans,
  complaints, cards, Jira. `write_activity_map` gives the 5 unmapped groups demo BRANCHIDs (9002 …) and audit dates in
  `tests/local/demo/activity_map.csv` (used only by `config/local.yaml orgmap`).
- Demo schemas: COREMIS, FINACLE, ERP (incl. `ERP_HR_KNOWLEDGE_TEST`), CARDZONE, MAIN, JIRA (incl. `ACTION_PLAN`), GRC
  (AUDIT_ENGAGEMENT / AUDIT_FINDING / REMOTE_AUDIT_CHECK / EXTERNAL_REVIEW / POLICY_DOCUMENT / INFOSEC_INCIDENT). The
  GRC / ERP_HR_KNOWLEDGE_TEST / JIRA.ACTION_PLAN tables and the SQL of SH_010 … SH_024, SH_047 are GUESSES (status
  REVIEW) — real names must be confirmed.
- `bank_golden.py` recomputes every automated indicator in plain Python from the raw rows (independent of SQL), keyed by
  definition name (`LOGIC[norm_key]`, `GRC_LOGIC`), and scores it with hand-written bands (`CANON`); non-canonical
  (broken) master scales are reported, not failed.
- `demo_check.py`: seed → check → run Q2+Q3 → fill manual templates (`fill_manual`) → verify → golden comparison →
  cases (read-only guards, rerun idempotency, rerun `--all` with no duplicate keys, structure change, auto, act_97
  practice, temporary `act_98_edge_cases`: timeout, UPDATE in a procedure, dependency cycle/failed, min_rows,
  SOURCE_NOT_READY, OUTPUT_SCHEMA, duplicate rows) and a per-definition table (500 defs). Writes
  `output/demo_report.{json,html}`; exit 1 on any mismatch.
- `tests/unit/test_catalog.py` parametrizes every indicator (1,388) and every shared def (50) without a DB; broken
  master scales of manual single-activity indicators are xfail (14) — fixed by hand in master.xlsx.
- `activities/act_97_practice/` (`example: true`, BRANCHID 1500 = retail network) has practice files whose footers hold
  commented ClickHouse check queries — never uncomment them in the file (they would be sent to Oracle).
- If a local run suddenly takes ~7 minutes, check `docker logs risk-oracle | grep 'Time drifted'`: Docker Desktop's VM
  was paused (host sleep); it is not a runner hang.

## Conventions and gotchas

- Never read or print `.env` (a PreToolUse hook blocks Bash commands that mention it); local uses Docker defaults.
- In ClickHouse view SQL alias every column (`r.x AS x`); qualify columns inside aggregates.
- `ClickHouseConnector.query` upper-cases result column names and binds only `{name:Type}` params present in the SQL;
  `OracleConnector` binds only the `:names` used (`oracle_binds_used`).
- `{{shared.x}}` expands to `(\n<select>\n)` — write `FROM {{shared.erp.sol_flow}} f`, not `FROM ({{shared…}})`.
- Oracle DDL in the demo uses `VARCHAR2(n CHAR)` (Cyrillic is 2 bytes per char).
- CI runs Python 3.10: no PEP 701 f-strings (no backslashes or same quotes inside `{…}`).
- Production runs on **Windows** (Task Scheduler: `deploy/windows/ri_auto.cmd`). Always pass `encoding="utf-8"` to
  file IO and subprocess; read user-edited CSV with `config.read_csv` (UTF-8/BOM or cp1251, `,`/`;`/tab — cp1251 has
  no ү/ө, so docs tell users to save "CSV UTF-8"); `ri.py` reconfigures stdout to UTF-8; `sql_version` hashes files
  with CRLF normalized; `.gitattributes` forces LF (CRLF for `.cmd/.bat`).
- Team workflow: one owner per activity folder; changes to `ri_runner/`, `config/`, `ddl/`, `templates/`, `shared/`,
  `activities/_shared/` go in a separate MR. Status lifecycle `TODO → IN_PROGRESS → REVIEW → TESTED → DONE`
  (`python ri.py status`); prod runs TESTED+ only. `/new-indicator` turns legacy SQL / procedures into an indicator file.
- The pre-restructure project (risk_indicators table, BRANCH_ID/SCALE columns, act_99 examples, scenario/hris checks)
  is preserved in `~/projects/RA_backup_20261014`.
