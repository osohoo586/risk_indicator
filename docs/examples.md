# Demo: стандарт банкны DB → SQL → ClickHouse → эталонтой тулгах

`python tests/local/demo_check.py` нь Docker дээр бүх урсгалыг ажиллуулж, үр дүн бүрийг **SQL-ээс үл хамааран
Python-оор тооцсон эталон**-той мөр бүрээр тулгана. Тайлан: `output/demo_report.html`.

## 1. Demo DB

[tests/local/bank_demo.py](../tests/local/bank_demo.py) — нэг seed-ээс (давтан ачаалахад ижил), банкны стандарт
нэршилтэй, баганын нэр ТААМАГ (бодит нэр өөр бол зөвхөн `shared/*.sql`-ийг засна).

| Schema | Хүснэгт | Юунд |
|---|---|---|
| COREMIS | MAIN (3 snapshot), GL_REPORT_DATA, GL_USER_BRANCH, CUSTOMER_COMPLAINT, GREEN_LOAN_PLAN, CUSTOMER_PLAN, CUSTOMER_ACTIVITY_MONTHLY, LOAN_MONITORING_QA, DOC_ARCHIVE_CHECK, LOAN_COMMITTEE_CHECK | бүтэц, BI тайлан, гомдол, төлөвлөгөө, шалгалт |
| FINACLE | SOL, CMG, GAM, LAM, LOAN_CLASS_HIST, LOAN_APPLICATION, **RA_LOAN_PKG** (procedure) | зээл, харилцагч |
| ERP | HR_ORG_DEPARTMENT, ERP_HR_POSITION, ERP_EMPLOYEE, ERP_EMPLOYEE_KEY, EMPLOYEE_HISTORY, ERP_HR_CURRENT_STATUS, HRM_EMP_FAMILY_PEOPLE, ERP_HR_APPRAISAL, ERP_HR_TRAINING, ERP_HR_STAFF_PLAN, ERP_HR_DISCIPLINE, ERP_HR_KNOWLEDGE_TEST | хүний нөөц (~1,100 ажилтан, 2023–2026 томилгоо, дэвшүүлэлт, шилжилт), мэдлэгийн тест |
| CARDZONE | CARD, TERMINAL, CARD_TXN (+ ClickHouse `cardzone_dwh.card_txn`) | карт |

GRC, ERP_HR_KNOWLEDGE_TEST, JIRA.ACTION_PLAN нь master-т "гарын" байсан 14 нийтлэг тодорхойлолтыг системээс тооцох
**ТААМАГ** хүснэгт ([dedup.md](dedup.md)) — бодит нэрийг тодруулж SQL-ийг засна (status REVIEW).

**Бүтцийн өөрчлөлт** (кодыг засахгүйгээр тусах ёстой): 2026-03-01-нд SOL 819 хаагдаж 818 үүссэн (ажилтнууд
TRANSFER — гарсанд тооцогдохгүй), 2026-02-01-нд ХНУГ-т 898 хэлтэс нэмэгдсэн. MAIN-ийн snapshot 2026-01-01, 03-01, 09-15.

**Local-ийн BRANCHID** (`tests/local/demo/activity_map.csv`): config-ийн ТОДРУУЛАХ 5 бүлэгт түр 9002, 9010, 9011, 9020,
9021; BRANCHID 2001-д түр SOL 731 — зөвхөн demo-д. Аудитын огноог GRC.AUDIT_ENGAGEMENT-аас тайлант өдрөөр
(`config/local.yaml audit:`) — тайлант өдрөөс өмнөх сүүлийн аудит; шинэ аудит орсон бол "аудитаас хойш" хугацаа
автоматаар шилжинэ.

## 2. Юуг шалгадаг

| Алхам | Шалгалт | Үр дүн |
|---|---|---|
| check | 1,388 үзүүлэлтийн static шалгалт | 0 алдаа |
| run --all -p Q2 -p Q3 | 34 нийтлэг SQL (762 үзүүлэлт) + 11 өөрийн SQL + act_97 | 1,546 (1,544 SUCCESS, 2 WARNING), **8 сек** |
| manual | 609 гарын үзүүлэлтийн Excel → жишээ утга → load | Q2 553, Q3 556 мөр |
| verify --all | source дээр дахин тооцоолж ClickHouse-тэй | 1,616 таарсан, 0 зөрүү |
| **эталон** | 1,382 үзүүлэлт × 2 улирал: утга, тоологч, хуваарь, SOL задаргаа, оноо, sol_id, file_name, period_start | **2,764 / 2,764** |
| тодорхойлолт бүрээр | 498 (+ act_97) тодорхойлолт: бүх үйл ажиллагааны үзүүлэлт нь эталонтой | **500 / 500** |
| нийт оноо | 35 үйл ажиллагаа × 2 улирал: Σ(жин × оноо) / Σ(оноотой жин), түвшин | **70 / 70** |
| тохиолдол | доорх хүснэгт | 20 / 20 |

Нийт ~52 сек (seed 3, run 8, manual 5, verify 12, тохиолдол ~20). Өмнө 17–120 сек байсан run нь нийтлэг SQL-ийг НЭГ
удаа, хуучин мөрийг тайлант өдөрт НЭГ DELETE-ээр, thread бүрт нэг холболтоор болсноор 8 сек.

Эталон нь өөрөө алдаа барьдаг эсэхийг SQL-ийг санаатай эвдэж шалгасан: SH_007-ийн хуваарийг `(эхэнд + эцэст) / 2`-ийн
оронд `эцэст` болгоход 35-аас 16 үйл ажиллагаанд зөрүү гарсан (бусад нь эхэнд = эцэст тул ялгаа гарахгүй).

**Тохиолдлууд:**

| Тохиолдол | Хүлээгдэх |
|---|---|
| Oracle / ClickHouse source-д бичих оролдлого | `SOURCE_WRITE_BLOCKED` (ORA-01456 / Code 164) |
| act_40-ийг дахин ажиллуулах | мөрийн тоо хэвээр (88 → 88), хуучин нь `ri_history`-д (+71) |
| `--all`-ийг дахин (4 thread зэрэг) | давхардсан түлхүүр 0, DELETE дахин оролдлого 0 |
| Бүтцийн өөрчлөлт | 2025-12-31: `808,…,816,819` → 2026-09-30: `808,…,816,818` |
| auto | бүгд шинэчлэгдсэн → 0; нэг үзүүлэлтийг устгахад → `ШИНЭ 1` → нөхөөд → 0 |
| Дадлагын folder (act_97) | Oracle, CARDZONE, өөр үзүүлэлтийн үр дүнгээс (dependency) — verify 0 зөрүү |
| Timeout (3 сек унтаж, хязгаар 1 сек) | `TIMEOUT` |
| Procedure дотор UPDATE | `FAILED SOURCE_WRITE_BLOCKED` |
| Dependency тойрог A ↔ B | хоёулаа `SKIPPED DEPENDENCY_CYCLE` |
| Dependency нь timeout болсон | `SKIPPED DEPENDENCY_FAILED` |
| `min_rows: 1000` | `VALIDATION_FAILED` |
| `source_check` = 0 | `SKIPPED SOURCE_NOT_READY` |
| VALUE багана алга | `FAILED OUTPUT_SCHEMA` |
| Давхардсан мөр | `VALIDATION_FAILED duplicate` |
| Хэвийн үзүүлэлт (алдаатайтай хамт) | `SUCCESS` — бусдын алдаа зогсоохгүй, run-ий exit code 1 |
| Алдааны тохиолдлын дараа | `verify --all` 808 таарсан, 0 зөрүү (зөв үр дүн хэвээр) |
