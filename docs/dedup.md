# Давхардлыг хэрхэн шийдсэн бэ

```bash
python ri.py dedup ~/Downloads/master.xlsx --open        # output/dedup_report.html — мөр бүрийн шийдвэр
python ri.py import ~/Downloads/master.xlsx --update     # master засагдвал бүтцийг дахин тааруулна (idempotent)
```

## Тоо

| | |
|---|---|
| master.xlsx-ийн мөр | 1,380 (35 үйл ажиллагаа) |
| Давтагдашгүй нэр = **тодорхойлолт** | **498** (882 давхардал хасагдсан) |
| Олон үйл ажиллагаанд давтагддаг | 50 тодорхойлолт → 932 мөр (24 нь 35 бүх үйл ажиллагаанд) |
| Ганц үйл ажиллагааны | 448 тодорхойлолт → 448 мөр |
| Файл | 1,380 → 498 (+ 35 activity.yaml) |
| Нийтлэг тодорхойлолтоос SQL-тэй | 34 (16 нь гарын) → 762 үзүүлэлт автомат |

## Бүтэц

```
activities/_shared/sh_007.sql                 НЭГ тодорхойлолт: нэр, аргачлал, шатлал, хугацаа + SQL

  shared:
    - {id: RI_40_1545, def: SH_007, weight: 1.5}          # Хүний нөөцийн эргэц
    - id: RI_40_1518                                     # Action plan биелэлт
      def: SH_010
      weight: 1.5
      scale_text: |                                      # энэ үйл ажиллагааны санаатай өөр шатлал
        1-96.1%-аас дээш
        …
activities/act_40_human_resources/ri_40_1520.sql   зөвхөн энэ үйл ажиллагааны үзүүлэлт (өөрийн SQL)
```

`ri.py run activities/_shared/sh_007.sql` нь 35 үйл ажиллагааны эргэцийг нэг SQL-ээр тооцно. SQL-ийг нэг удаа
засахад 35 үйл ажиллагаанд тусна; `auto` нь өөрчлөгдсөн гэж 35-ыг дахин ажиллуулна.

```bash
python ri.py status RI_40_1545                               # аль мөр, аль тодорхойлолт, юуг дарсан
python ri.py run  --env local activities/_shared/sh_007.sql -p 2026-Q3                  # 35 үйл ажиллагаа
python ri.py run  --env local activities/act_40_human_resources/activity.yaml -p 2026-Q3  # act_40-ийн нийтлэг мөрүүд
python ri.py test SH_010 --env local                         # тодорхойлолтыг бүх үйл ажиллагаанд тестлэх
pytest tests/unit/test_dedup.py tests/unit/test_catalog.py -q    # дүрэм, manifest, үзүүлэлт бүр
```

## Нэгтгэхгүй, хүн шалгах

- **Гэр бүл (24, 62 үзүүлэлт):** нэрийн төгсгөлөөрөө ялгаатай — "Нийт ритэйл харилцагчийн тоо-УБ / -ОН",
  "Стандарт хугацаанд хүсэлт шийдвэрлэсэн хувь-бичил / жижиг / дунд / том санхүүгийн түрээс". Утга нь өөр тул тусдаа
  үзүүлэлт; автоматжуулахдаа SQL-ийг НЭГ удаа бичээд бусад нь `sql_from: …` + `params: {p_region: ОН}`
  (жишээ: SH_024 = SH_023-ийн SQL, `p_data_type: ХАРИЛЦАГЧ`).
- **Төстэй нэр (18):** "Зээлийн scoring-ийн …" ↔ "Зээлийн rating-ийн …" г.м. — өөр байж болох тул автоматаар
  нэгтгэхгүй; ижил бол master-т нэрийг нэгтгэж `import --update`.

## master-т гарын, системээс тооцох болсон

master-д "Автоматжуулах: Үгүй" боловч өгөгдөл нь системд байх 14 нийтлэг тодорхойлолт (457 үзүүлэлт) — demo DB-д
ТААМАГ хүснэгтээр, бодит нэрээр засна:

| Тодорхойлолт | Эх сурвалж |
|---|---|
| SH_010 Action plan биелэлт | JIRA.ACTION_PLAN — хугацаандаа шийдвэрлэсэн % |
| SH_011 Бүтцийн өөрчлөлт | COREMIS.MAIN snapshot (аудитын өдөр ↔ тайлант өдөр) |
| SH_012 Дүрэм журам шинэчлэгдсэн | GRC.POLICY_DOCUMENT — хамгийн удаан шинэчлэгдээгүй журмын насжилт |
| SH_015 Монгол банкны үнэлгээ, SH_016 Хөндлөнгийн аудитын зөвлөмж | GRC.EXTERNAL_REVIEW |
| SH_017 … SH_020 Аудитаас хойшхи хугацаа, үнэлгээ, өндөр эрсдэлтэй асуудал, follow up | GRC.AUDIT_ENGAGEMENT, AUDIT_FINDING (`shared/grc/last_audit.sql`) |
| SH_021 Зайны аудит | GRC.REMOTE_AUDIT_CHECK |
| SH_022 Мэдлэгийн түвшин | ERP.ERP_HR_KNOWLEDGE_TEST |
| SH_023 / SH_024 Банкны / харилцагчийн нууц задруулсан | GRC.INFOSEC_INCIDENT (нэг SQL + p_data_type) |
| SH_047 Салбарын захирлын орон тоо сул байсан хугацаа | ERP.EMPLOYEE_HISTORY |

Аудитын огноо ("аудит орсноос хойш") ч мөн GRC-ээс тайлант өдрөөр (`config audit:`) — шинэ аудит орвол бүх
"аудитаас хойш" үзүүлэлтийн хугацаа автоматаар шинэчлэгдэнэ.
